# 喵指令：管理员对学姐的指令级操作

> 实现：src/plugins/dl_senpai/admin_commands.py（解析 + 执行）
> 登记：src/plugins/dl_senpai/core/commands/admin.py（声明式注册）
> 状态：src/plugins/dl_senpai/admin_control.py（静默状态）
> 测试：tests/test_admin_commands.py

## 一、用法

**指令名用英文，写法是「喵 + 指令」**（2026-10-28 起）：

    喵mute @某人 10m
    喵recall
    喵help
    喵kick @某人 拉黑

为什么换成英文：中文指令必须带分隔符（`喵/禁言`）才能定出边界，否则
「喵禁言」和「喵禁言语」分不开；英文天然有词边界，可以直连写，少一个字符、
少一次切输入法。

**中文别名一条都没删**，下面这些写法仍然有效：

    喵/禁言 @某人 10m     ← 中文别名 + 斜杠
    喵禁言 @某人 10m      ← 中文别名无斜杠（旧写法）
    /mute @某人 10m       ← 市面 bot 的写法
    #sl @某人 10m         ← 同上
    ！mute @某人 10m      ← 同上
    喵 / mute 10m         ← 斜杠两边有空格也认
    喵／mute 10m          ← 全角斜杠也认

实现上不靠「每条命令各写一遍前缀」：CommandRegistry 在匹配前统一做一次
归一化（喵/指令 → /指令，全角符号 → 半角），所以**新增命令自动享受同一套前缀规则**。

**喵help 发的是合并转发，内容按身份分叉**（2026-10-28 加）：

- **主人**：47 条管理指令按组排出，每组标题标「（主人专属）」，末尾再附一张
  「所有人可用 · 19 条」，一眼能分清哪些是自己的活、哪些是群友自己能玩的。
- **群友**：只发「所有人可用」那张，并说明「带喵的是主人的指令，发了没人应」——
  不然他们对着 47 条不属于自己的指令，只会以为功能坏了。

群友发「喵help」会有回应，是这条规则唯一的例外（`Command.open_admin_prefix`）。
别的指令没放开：群友发「喵kick」依旧静默跳过。

只想看一组就 `喵help 群管`，只记得关键词就 `喵help 撤回`。群友搜到主人的指令时，
会明确回「这是主人的指令」，而不是「没这个东西」。

指定「对谁操作」有三种方式，任意一种都行，也可以叠加：

1. **@ 他**：喵mute @小明 10m
2. **引用他的消息**再发指令：喵mute（最不容易认错人，群里改名也不影响）
3. **直接写 QQ 号**：喵mute 123456789 10m

时长写法：10（秒）/ 10s / 10秒 / 10m / 10分 / 1h / 1小时 / 2d / 1天 / 1w / 1周。
禁言的裸数字按**秒**（与 QQ 原生一致）；喵silence 的裸数字按**分钟**
（说「闭嘴十分钟」没人说「六百秒」）。

**不猜名字**：按昵称匹配目标需要拉全量群成员表，既慢又容易被同名/改名骗过。
要么 @、要么引用、要么写 QQ 号。

### 指令分两层（2026-10-28 定）

**带「喵」字 = 管理员专用；不带喵 = 所有人可用。**

| 层 | 格式 | 谁能用 | 例子 |
|---|---|---|---|
| 管理员指令 | 必须带「喵」 | 只在 DL_SENPAI_ADMIN_QQ 名单里的人 | 喵mute、喵recall、喵/人设 学姐、喵reset 卡片 |
| 群友玩法 | 不带喵，直接说 | 群里所有人 | 签到、打卡、积分商店、好感度、抽签、骰子、群信息、我的警告 |
| 新人认证 | 不带喵 | 待认证的新人 | 认证 |

这条分层在**结构上**强制，不靠各条命令的正则巧合：

- 每条管理员指令都带 permission="admin" 标记；
- CommandRegistry 匹配时，只要原文以「喵」开头，就**只考虑带这个标记的命令**。

结果是「喵签到」既不是管理员指令、也不会退化成签到——它匹配不到任何
指令，直接交给 AI 正常接话。这样以后就算给签到加上「/签到」支持，
带喵的写法也不会突然变成人人可用的玩法。

顺手统一的一件事：非管理员发管理指令（含 喵/人设、喵reset）时**不再回话**，
而是静默跳过、把消息交给 AI。回一句「只有管理员能用」等于向全群复述
谁的权限最高，没必要。

## 二、配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| DL_SENPAI_ADMIN_QQ | 空 | 管理员 QQ 号，**可多个**，逗号/分号/空格/全角空格分隔 |
| DL_SENPAI_ADMIN_ALLOW_GROUP_ADMIN | false | 是否允许 QQ 群原生管理员/群主也用管理指令 |
| DL_SENPAI_ADMIN_SILENCE_PATH | 空 | 静默状态文件路径，空 = data/dl_senpai/admin/silence.json |
| DL_SENPAI_ADMIN_WARN_PATH | 空 | 警告记录文件，空 = data/dl_senpai/admin/warn.json |
| DL_SENPAI_ADMIN_BLACKLIST_PATH | 空 | 黑名单文件，空 = data/dl_senpai/admin/blacklist.json |
| DL_SENPAI_ADMIN_WORDS_PATH | 空 | 群词库文件，空 = data/dl_senpai/admin/words.json |
| DL_SENPAI_ADMIN_SCHEDULE_PATH | 空 | 定时消息文件，空 = data/dl_senpai/admin/schedule.json |

管理员名单的**三级回退**（在 PluginConfig.admin_id_set 里实现一次）：

    DL_SENPAI_ADMIN_QQ  →  DL_SENPAI_AGENT_ADMIN_QQ  →  DL_SENPAI_OWNER_IDS

即：配了新的就用新的；没配就继续用老字段；三个都空 = **谁都不是管理员**。
默认关闭而不是默认全开——反过来写就是一个人人可用的后门。

为什么管理员名单和「高风险工具名单」（agent_admin_qq）分开：
前者的语义是「谁能在这个群里管她」，后者是「谁能碰这台机器上的文件和命令」。
群里可以多一个人帮忙看群，但绝不能因为「帮忙看群」就顺手拿到 shell。
没单独配 admin_qq 时会回退到 agent_admin_qq，所以老部署升级后行为不变。

### 这几条为什么值得单独说

### 违禁词为什么值得单独说

**它和词库是反的。** 词库要求「整句等于触发词」才回——不然正常聊天里只要有个「天气」
她就会插一句预设答案。违禁词要求「消息里包含就算」——因为骂人的话从来不会独立成句，
「你个傻逼」和「傻逼」都得拦。同一个 `in` 判断，两个功能的正反面。

**触发后做什么：**

1. 先撤消息（她不是管理员就撤不动，撤不动也照样记警告）；
2. 记一次警告，和 `喵warn` 共用同一本账——管理员手动警告和自动警告不该是两套计数；
3. 满 3 次禁言 **1 天 23 小时 59 分**（172740 秒），**禁完清零**。

第 3 条里的「清零」是关键：不清的话第 4 次会立刻又触发禁言，等于判了无期，
而这恰恰是很多群管 bot 的默认行为——它把「满 3 次」实现成了「从第 3 次起永久」。

**谁能不被它管：** 主人，以及开了 `DL_SENPAI_ADMIN_ALLOW_GROUP_ADMIN` 时的群管。
不豁免的话，主人自己在群里吐槽一句就被自己禁言了，而且因为他也看不到「自己被警告」
的原因，排查起来极难。以「喵」开头的消息同样跳过——那是管理指令，
`喵bad add 傻逼` 不能被自己刚加的词拦下来。

**关掉不丢词表：** `喵bad off` 只停检测，词还在。尺度不对时可以先关掉，
不用重新录一遍。


**词库会自动接管消息**：命中就回预设文本并结束，不进 LLM。所以它放在
玩法指令（签到/商店/好感度）之后、AI 之前 —— 不会抢走「签到」，
但能先于模型生效。整句匹配是刻意的：包含匹配会让「今天天气不错」被
一个「天气」关键词拦下来。

**黑名单只拦「她的话」**：被拉黑的人发消息她不接（包括词库回复），
但签到、积分商店、好感度照常可用 —— 积分是群友自己的资产，
不该因为管理员的一句气话被冻结。

**定时消息落盘**：进程重启（改配置、更新代码）不会丢。发失败不重试，
宁可不发也不在群里刷三遍同一句话。

## 四、行为约定

- **权限不足时不吞消息**。命中管理指令但没权限 → 抛 AdminDenied，Router 静默跳过，
  消息继续交给 AI 正常处理。既不会回「你没有权限」（等于向全群复述谁有权限），
  也不会像石沉大海。
- **管理指令一定短路**（consume=True）：踢完人不该再补一句撒娇。
- **每条操作都写审计日志**：
  - admin_command.invoked —— 谁、在哪个群、执行了什么、参数
  - admin_command.denied —— 谁试图用什么指令被拒绝了
  - admin_command.silence —— 静默的时长与操作者
- **静默是群级的**，只影响该群；私聊、别的群照常。

### 待移植（还没做，别以为已经有）

上一轮列的清单里，**禁言列表、词库、黑名单、定时消息、群公告/文件/相册/精华
的查看**都已经做掉了。仍然没有的是这些：

| 指令 | 语义 | 为什么还没做 |
|---|---|---|
| 欢迎词 / 告别词自定义 | 入群欢迎文案 | 现有人设已接管欢迎语，改了会和人设风格打架 |
| 签到/好感排行导出 | 导出 CSV 或图片 | 榜本身有，导出没做（要图片渲染管线） |
| 多级分权 | 超管 / 群管 / 普通 | 目前两档：管理员与非管理员（群管可开） |
| 操作回滚 | 撤销一次管理操作 | 群管 API 大多没有逆操作（踢人撤不回） |
| 群文件/相册的写操作 | 删文件、清相册 | 删除类操作风险高，且协议端支持不一致 |
| 群精华写入 | 把消息设为精华 | 协议端没有标准接口 |
| 刷屏自动检测 | 触发规则自动处置 | 产品决策未定：该她判断还是规则判断 |
| 点歌 | 语音点歌 | 依赖外部音乐 API 与版权，不适合内置 |
| 天气 | 天气查询 | 要外部 API key；她已经能联网查 |
| 翻译 | 翻译指令 | 她本身就会翻，指令版只是转发，没有增益 |
| 概率/冷却在线调整 | 不改 .env 调插嘴 | 要改插嘴判定主链路，风险高；**喵reload** 已能让 .env 改动即时生效，边际收益不大 |


## 六、扩展方式

新增一条管理指令只需三步（无需改动 Router 或 registry 主体）：

1. 在 admin_commands.py 写一个 `async def _h_xxx(ctx, args, raw)`；
2. 在 `_HANDLERS` 里加一行 `"xxx": _h_xxx`；
3. 在 core/commands/admin.py 的 ALIASES 与 DESCRIPTIONS 里各加一项。

优先级固定为 PRIORITY_ADMIN=30（比群友玩法 50 先匹配，比新人认证 10 后），
不用再挑「一个不打架的数字」。

### 群友日常（member_commands.py）

2026-10-28 补的一批。原来群友只有「签到 / 商店 / 好感度」三件事可做，
发「喵help」看到的就是那 8 条，太单调。这批全是**复用已有实现**加出来的入口，
没有一份重复逻辑——`群信息` 和 `喵groupinfo` 走的是同一个 handler。

| 发什么 | 作用 |
|---|---|
| 抽签、求签、运势、今日运势 | 今日签文，可带事项：`抽签 今天面试` |
| 骰子、掷骰、roll [NdM] | 掷骰子，默认 1d6，可写 `骰子 2d6` |
| 计算、算一下 <算式> | 算数，不走模型，结果确定 |
| 我的信息、我是谁、我的档案 | 自己的名片、身份、等级、入群时间 |
| 群信息、本群信息、群资料 | 群名、人数上限、建群时间 |
| 群公告、看公告 | 本群公告列表 |
| 群文件、本群文件 | 群里上传过的文件 |
| 禁言名单、谁被禁言了 | 现在谁在禁言里、各剩多久 |
| 管理名单、本群管理 | 群主和管理员是谁 |
| 我的警告、我的违规 | 自己被警告了几次、为什么 |
| 改名片 <新名字>、我要改名 <新名字> | 改自己的群名片 |

**这些正则都是整句锚定的。** `算一下他会来吗`、`群公告里写了什么`、`运势真好`
都不会被当成指令吃掉——被短路的用户永远等不到回复，而且他不知道自己被拦了。
宁可少认一种说法，也不能吞掉正常聊天。

**只查自己，不给查别人。** `我的信息` 只查发指令的人；想查别人的档案，
那是 `喵whois`（管理员）。「禁言名单」和「管理名单」公开是因为它们本来就写在
群成员列表里，藏起来只会让「为什么我被禁言」变成吵架。
