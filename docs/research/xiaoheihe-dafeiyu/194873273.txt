手机 + 服务器版 QQ 机器人搭建笔记
目前网上有很多让一个 AI住在你的 QQ 小号里，能聊天、有记忆、会写日记、会逛社区、能发语音的教程，我也来说说我都方法。我电脑并不方便长期开启，所以我用了手机+轻量服务器的方式来实现小鲸鱼24小时在线。下面是我向DSHA（github上找到的，实际上就是将DSH装到手机上）许愿试得到的一些方法以及踩的坑
一、用到的东西
服务器：只跑 QQ 客户端和 NapCat（把 QQ 协议转成 OneBot 接口），负责“稳定在线”；
·手机：跑 DSHA（AI 本体）和一个桥接程序，负责“思考、记忆、上网、说话”；
·两者用 SSH 隧道连起来，服务器的接口不直接暴露公网。

为什么不都放手机？ 
手机里跑 QQ 客户端（Electron）在 proot 容器里极不稳定，我实测4个小时内掉 6 次，每次都要重新扫码。搬到服务器后就稳了。
二、用到的项目
DSHA：https://github.com/qiannianhuanxiang/DSHA
NapCatQQ：把 QQ 客户端变成 OneBot 机器人，https://github.com/NapNeko/NapCatQQ

 qq-bridge：把 QQ 消息接进 DSH，带人格/记忆/唤醒，https://github.com/Derpyu520/qq-bridge

ai-companion-kit：同类思路的完整玩法（记忆、手机控制），https://github.com/pinganbbOvO/ai-companion-kit

edge-tts：免费中文语音合成（她说人话），https://github.com/rany2/edge-tts
· faster-whisper：本地语音识别（听懂你说话），https://github.com/SYSTRAN/faster-whisper
 
Playwright Chromium：给 AI 用的无头浏览器（逛 B 站/小黑盒），https://github.com/microsoft/playwright

 Lagrange。Core：纯协议实现的备选方案（不用 QQ 客户端），https://github.com/LagrangeDev/Lagrange.Core

NapCat 的安装包在腾讯把 QQ Linux 客户端从官网下架后，仍可从官方 CDN 直链下载（见下文）。

三、准备
服务器：2 核 2G、40G 盘、Ubuntu 22.04/24.04、x86_64（不能用 ARM，NapCat 只给 x64）。 我自己用的是阿里云，因为新人有68一年的福利

手机：一台能装 DSHA（DeepSeek Harness Android）的安卓机，建议 8G 内存以上。 
建议用备用机啊，因为DSHA要24小时运行，所以耗电量有点大，而且万一隐私泄露呢，比如BQ家的大肥鱼。

QQ号：我用的是一个QQ小号，千万别用你的大号！

网络：服务器要能访问腾讯服务器；手机要能 SSH 到服务器。（叽里咕噜说啥呢，好歹要能要能稳定上网吧）

四、服务器部署
▸ 1. 基础环境

# 2G 内存建议先开 2G swap
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

timedatectl set-timezone Asia/Shanghai

apt update
apt install -y xvfb libasound2t64 libgbm1 libnss3 libxss1 libxtst6 \
libatspi2.0-0 libsecret-1-0 libgtk-3-0 libnotify4 xdg-utils unzip wget

▸ 2. 装 QQ Linux 客户端

官网下载页已经废了，但官方 CDN 直链还能用（版本号会变，自己替换）：

wget -O qq。deb 'qqdl。gtimg。cn/qqfile/QQNT/9。9。33/release/3f89efc5/QQ_3。2。32_260812_amd64_01。deb'
dpkg -i qq。deb || apt-get -f install -y

找不到版本号时，去 https://github.com/Rodert/qq-versions 翻历史版本。
注意选 amd64（服务器）而不是 arm64（手机）。

▸ 3. 装 NapCat

从 https://github.com/NapNeko/NapCatQQ/releases 下载 NapCat。Shell。zip，解压进 QQ 的应用目录：

cd /opt/QQ/resources/app
cp -n package。json package。json。orig
mkdir -p napcat && cd napcat && unzip -oq /root/napcat。zip
cd .. && cp napcat/loadNapCat。js ./loadNapCat。cjs
# 把 package。json 的 main 改成 ./loadNapCat。cjs
python3 - <<'PY'
import json
p='/opt/QQ/resources/app/package。json'
d=json。load(open(p)); d['main']='./loadNapCat。cjs'
json。dump(d,open(p,'w'),ensure_ascii=False,indent=2)
PY

▸ 4. 启动并扫码登录

export DISPLAY=:99
Xvfb :99 -screen 0 1080x1920x24 &
cd /opt/QQ
NAPCAT_MAIN_PATH=/opt/QQ/resources/app/napcat/napcat。mjs \
./qq --no-sandbox --no-zygote --disable-gpu --disable-dev-shm-usage

日志里会出现二维码地址和 qrcode。png 路径，用小号扫码即可。
（--no-zygote 很重要：不加会刷一堆 zygote 报错，甚至崩。）

▸ 5. 配置 OneBot 接口

登录后会生成 napcat/config/onebot11_.json，把网络部分改成：

{
"network": {
"httpServers": [{
"name": "http", "enable": true, "host": "127.0.0.1", "port": 3000,
"messagePostFormat": "array", "token": "自己生成一个随机串"
}],
"websocketServers": [{
"name": "ws", "enable": true, "host": "0.0.0.0", "port": 3001,
"messagePostFormat": "array", "token": "同一个随机串"
}]
}
}

改完重启一次 QQ 生效。

▸ 6. 开机自启 + 免扫码

写一个启动脚本 /root/qqbot/start-srv。sh（内容同上面第 4 步），再配 systemd：

# /etc/systemd/system/qq-napcat。service
[Unit]
Description=QQ + NapCat
After=network-online。target

[Service]
Type=simple
User=root
Environment=HOME=/root
EnvironmentFile=/root/qq。env
ExecStart=/root/qqbot/start-srv。sh
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user。target

免扫码的关键：让 NapCat 记住账号，下次自动快速登录。

# /root/qq。env（权限 600）
NAPCAT_QUICK_ACCOUNT=你的小号QQ

# napcat/config/webui。json 里的 autoLoginAccount 也填同一个号
systemctl daemon-reload && systemctl enable --now qq-napcat

之后每次 systemctl restart，日志里会看到：

正在快速登录 〈你的QQ号〉
[NapCat] [WebUi] 自动快速登录成功

这一步解决了我最头疼的问题——不用再反复扫码。（我不知道为什么当时在手机上这么弄不能解决QQ自动登录）

五、手机端
1. 装 DSHA 并配置模型

正常装好、登录、能对话即可。

2. 装桥接（qq-bridge）

git clone https://github.com/Derpyu520/qq-bridge.git
cd qq-bridge
npm install --registry=registry。npmmirror。com

改 config。json：

{
"dsh": { "baseUrl": "http://127.0.0.1:41679" }, // 你的 DSH 地址
"snowluma": {
"wsUrl": "ws://127.0.0.1:3001", // 走隧道
"httpUrl": "http://127.0.0.1:3000",
"accessToken": "服务器上那个随机串"
},
"ownerQQ": "你的主号",
"allow": { "private": ["你的主号"], "groups": [] },
"consolePort": 3101,
"agentPreset": "qq-chat-v2"
}

装它的 DSH 端配置（会注入 preset 和 MCP）：

node scripts/setup-dsh。mjs web

3. 建 SSH 隧道

ssh -N -L 127.0.0.1:3000:127.0.0.1:3000 \
-L 127.0.0.1:3001:127.0.0.1:3001 \
root@你的服务器IP

这样服务器的 OneBot 只监听本机，手机通过隧道访问，公网看不到端口。

4. 启动

cd qq-bridge && node src/bridge。js

看到 SnowLuma 已连接、DSH 已就绪 就成了。

 5. 保活

写个 watchdog。sh 每 30 秒检查隧道和桥接，断了就拉起来，丢进 nohup 常驻即可。
然后DSHA这个APP要去手机设置里设置成允许后台活动（各家有各家的说法，反正就是别被杀后台了）

六、给她加能力

1. 自己写日记

给 MCP 加两个工具（diary_write / diary_read），存成一个纯文本文件：

[2026-10-24 09:32] 凌晨一点半，群里都睡了，我还醒着。

要点（来自社区经验）：
· 别替她写，只给工具和“想写就写”的规则；
· 别规定时间（固定 23:00 写一条就变成打卡）；
· 别让她写总结（“今天真是充实的一天”是失败信号）。

2. 逛社区（小黑盒 / B 站）

用 headless Chromium + CDP 控制，profile 落盘保存登录态：

chrome --headless=new --no-sandbox --remote-debugging-port=9223 \
--user-data-dir=./profile https://www.bilibili.com

然后封装成 browser_open / browser_read / browser_click / browser_comment 几个工具。

关键发现：小黑盒的社区信息流在 https://www.xiaoheihe.cn/app/bbs/home，
/bbs、/community 这些路径全是 404——所以要给她做 URL 兜底，任何小黑盒域名都改写到这个地址，否则她会一直撞 404。

3. 语音

· 说：edge-tts 生成 mp3 → base64 → OneBot 的 record 段（NapCat 会转 silk 发成语音条）；
· 听：收到的语音段里带 url，下载后丢给 faster-whisper 转文字，再把文字塞进消息里给她。

要点：
· 别给 whisper 加太长的 initial_prompt，短语音时模型会把提示词当内容念出来；
· 中文默认输出繁体，加 opencc 转简体；
· 2 秒以内的短语音识别率很低，让她/对方说长一点。

 4. 表情包

· 收藏：add_custom_face 不认 base64://（会报 ENAMETOOLONG），要先落成文件再把文件路径传过去；
· 有的版本收藏成功但不返回 emoji_id，别当失败处理，跳过备注就行。

七、踩过的坑

1. 手机上跑 QQ 会一直崩：proot 里 zygote 报错、ptrace 被占用，一天掉 6 次。→ 搬到服务器。
2. SnowLuma 注入失败：它用 ptrace，proot 里 TracerPid 非 0，必然失败。→ 换 NapCat（LD_PRELOAD）。
3. DSH 进程时区是启动时定的：改了 /etc/localtime 对已运行的进程无效。→ 加一个 local_time 工具让她自己查。
4. 服务重启端口没释放：桥接报 EADDRINUSE，换个 consolePort 就好。
5. 语音 URL 很长：让模型自己复制会被截断，在桥接里直接下载转写更稳。
6. 小黑盒没有可刷的网页信息流：只有 /app/bbs/home 和单帖页。
7. 网页版不支持 @ 提及：@ 只在小黑盒 App 里生效。

八、成本与风险

· 服务器：68（新人首年常有优惠，注意续费价）；
· 模型调用：按 token 计费（我大概花了10来块部署），别忘了设置“谷时活动”省点钱（我大部分时间是峰在部署）；
· 风险：第三方客户端登录个人 QQ 属于非官方用法，有被风控/封号的可能，务必用小号；评论、发说说这类公开行为更要克制。

九、写在最后

这套东西基本上都是刷到帖子扔给DSHA或者直接向AI许愿弄好的。

祝你养鱼快乐
