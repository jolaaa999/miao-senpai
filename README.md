# QQ 深度学习学姐机器人

基于 **NapCat（OneBot v11）+ NoneBot2** 的 QQ 群聊机器人。人设是热情可爱的深度学习学姐：群内 `@` 必回，未 `@` 时低频率自然插嘴；模型走你自己的 **OpenAI 兼容中转站**（默认模型名 `gpt-5.6`）。

## 架构

```
QQ 群 → NapCat → 反向 WebSocket → NoneBot2 → dl_senpai 插件 → 中转站 GPT
```

## 环境要求

- Python 3.12+
- 可用的中转站 `API Key` + `Base URL`
- [NapCat](https://github.com/NapNeko/NapCatQQ) + 机器人 QQ 号

## 使用方式

- 群里 `@机器人` 提问（深度学习或闲聊均可）
- 不 `@` 时约 3% 概率插一句，带冷却，深度学习关键词会略提高概率
- 对话按群保留最近约 20 轮短期记忆（`data/dl_senpai/memory/`）
- 开启热梗后，学姐会参考近期微博/抖音/B站等热榜标题轻度接梗
- 开启联网后，问新闻/天气/股价等时效问题时会**实时检索**再回答（闲聊不会每句都搜）
- 开启浏览器后，可说「去淘宝找衣服」「pixiv 找壁纸」「截图这个网址」，学姐会真的打开网页并把图发到群里
- 指定群可「签到」：连续天数、积分、称号、每日任务、概率表情包

## 说话长度与碎句

默认**一条回复就发一条**（`DL_SENPAI_BUBBLE_MAX=1`）。拆成 2~3 条发出去在群里像刷屏，
真人不会把一句话切成三条发。拆条机制本身还在，设 2~3 就能恢复。

长度纪律注入在**系统提示词最末**——人设中段的规则压不住模型输出长度，最后读到的那段才管用。
内容：默认 1~2 句、一般不超过 60 字；被问「怎么做」时先给一句结论、最多补两三条理由；
只有对方明确说「详细讲讲」「给个步骤」才展开成教程。关掉用 `DL_SENPAI_REPLY_BREVITY_ENABLE=false`。

> 原先人设里写着「答疑目标 400~1500 字」，她照做了——群里问一句 GitHub 怎么入门，
> 她回三段小作文。不是话痨，是规则让她写那么长。
### 长文用合并转发

正文超过 `DL_SENPAI_FORWARD_MIN_CHARS`（默认 **400** 字）时，不再连发气泡，改用**合并转发**
（聊天记录卡片）发一条。点开是按小标题分好的若干节，每节不超过 `DL_SENPAI_FORWARD_NODE_CHARS`
（默认 **600** 字）。

切点按「小标题 → 空行 → 列表项 → 句子」的顺序找，不按字数硬切——否则「一、结论」会跟它的正文
被劈到两个节点里。卡片发不出去时自动退回逐条发送。设 `DL_SENPAI_FORWARD_MIN_CHARS=0` 关闭。

配套的格式要求写在人设【长文怎么写】里：300 字以上先一句结论、后面一点一行、块间空行，
不允许连续四行不分段的整块。

## 防风控：发送闸门 + 真·正在输入

腾讯判断机器人最看的不是你打几个字，而是**失败之后还一直重试**。
所以发送路径上有两道闸门，在真正调用 send 之前生效：

- **熔断器**：连续失败 3 次就停 180 秒，期间连尝试都不发起（不是「失败了再等」）。
- **频率上限**：默认 6 条/分钟、80 条/小时，跨群全局计数。

另外开了真「正在输入」（OneBot 扩展 `set_input_status`），对方 QQ 上会真的显示打字状态。
但上报太勤本身就是机器人特征（原项目一天 175 次，反而暴露了），所以限制为：
短消息不发（不足 20 字）、至少隔 45 秒、35% 概率。**NapCat 不一定实现这个接口**，探到不支持会自动永久关闭。

打字时长改为按字数算（约 110ms/字，单条封顶 3 秒）——固定延迟下回 3 个字和 30 个字等一样久，本身就是机器味。

配置见 `.env.example` 的 `DL_SENPAI_SEND_*` / `DL_SENPAI_TYPING_*`。这几项的默认值不要调大。

## 叫得动：主人必醒 + 消息合并

**主人必醒**：把 QQ 号填进 `DL_SENPAI_OWNER_IDS`，这些人说话就跳过冷却和骰子。
她刚回过话、正在冷却时你再说一句，本来会被静默晾着——「明明在却不理我」比不回更伤。
但短句过滤仍然生效：「嗯」「草」这类不走 AI，否则她对每个语气词都要回一句。

**消息合并窗口**：对方连着发几条时（「那个 PPT」「就是上次说的」「你有吗」），
先攒 2.5 秒（私聊 1.5 秒）再当成一句话回一次。真人不会追着每条都答一句。
注意跟 `DL_SENPAI_BUBBLE_MAX` 方向相反：那个管她的话拆成几条，这个管对方的话攒成几条。
代价是每条回复都会晚一个窗口，觉得慢就把 `DL_SENPAI_BATCH_WINDOW_GROUP_MS` 调小或直接关掉。

## 改完先自检

```powershell
python scripts\check.py    # 语法 → 导入 → 冒烟不变量，两秒钟
```

不连网、不调模型、不起服务。它会把插件包里 150 多个子模块全部 import 一遍，
语法错误和导入错误当场就能拦住——不用重启一次 bot 再等出错。
提示词拼装后的总字数也在这里打出来，方便观察人设有没有越写越长。

## 提交前自检

```powershell
python scripts\check_leaks.py          # 扫已跟踪的文件
python scripts\check_leaks.py --all    # 连未跟踪的一起扫
```

查三样：真密钥（`sk-` / GitHub token / 私钥，命中即退出码 1）、真实群号、本机绝对路径。
后两类只提示不拦——测试里用真实群号很常见，全拦下来只会让人把这个脚本关掉。
跟 `validation/privacy.py` 分工不同：那个是运行期把日志里的 QQ 号脱敏，这个是提交前扫仓库文件。

**干跑**（改完人设/长度，想连问十句看语气但不想真发出去）：

```powershell
python scripts\dryrun.py --search off --group 群号 "在吗"
```

完整链路照跑（记忆、提示词、工具、模型），只在发送那一步换成打印，不会发出任何消息。

## 她自己的日子（日记 + 定时静默唤醒）

记忆是「关于你的事」，日记是「她自己的一天」——这两样分开存、分开用。

- **日记**：`data/dl_senpai/diary/index.jsonl`（机器读）+ 每天一份 `YYYY-MM-DD.md`（人直接翻）。
  只有最近 3 条会进提示词，多了会把她拽在旧事里、接不上眼前的话。
- **静默唤醒**：默认**关闭**。打开后每 2.5 小时问她一次「现在是你自己的时间，想干点什么」，
  她自己决定写日记、在群里冒一句、或者什么都不干。凌晨 3–8 点不叫，每天最多 6 次。
- **主动发言必须配白名单群**（`DL_SENPAI_OWN_LIFE_GROUPS`）。留空 = 只写日记、绝不发消息。

> 定时发的第一条说说，观众一眼就能看出是机器人——因为它不是想说，是到点了。
> 所以这里的机制是「叫醒她，让她自己决定」，而不是定时发帖。

配置见 `.env.example` 里的 `DL_SENPAI_DIARY_*` / `DL_SENPAI_OWN_LIFE_*` 两段。

## 不乱说话、也不失忆

**重复消息去重**（`DL_SENPAI_DEDUPE_*`）：NapCat 断线重连会重放没 ack 的事件，
同一条群消息可能进来两次。没有这层，她会对着同一句话回两遍，而且第二遍还带着
刚更新过的上下文，答得跟第一遍不一样——看起来就是「抽风」。
判重按 `(bot, message_id)`，默认窗口 5 分钟、最多记 512 条。
命中重复的整条丢掉，**连观察者都不跑**：观察者会往「最近聊天流水」里写，
重复写进去，她上下文里同一句话就出现两遍，比不回更糟。

**语气判定（实测有用，也有用不上的边界）**

每轮先判一次「这句是吐槽还是真倾诉」，结论贴到提示词最末。实测（每句 3 遍、54 次调用）：

| 方案 | 吐槽时进安慰 | 吐槽组字数 | 真倾诉时有安慰 |
|---|---|---|---|
| 不开判定 | 33% | 51~172 字 | 22% |
| 只在提示词末尾写规则 | 33% | 51~172 字 | 55% |
| 让模型判一句 / 让它改写这句 | 33~50%（不稳定） | — | — |
| 本轮写「别超过 30 字」 | 11% | 34~164 字 | 33% |
| **出站确定性过滤（最终采用）** | **0%** | **30~50 字** | **44%** |

最后一行是现在的做法，两个过滤器，都不调模型、不加延迟：

- **剪安慰小句**：判定为吐槽且命中安慰词，按逗号级把这个小句删掉。
  只删小句不砍整句，否则有用的话会被一起扔。删完不足 8 字、
  或剩下「可以这样回」这种元话语残渣，就退回原文。
- **按句截字数**：对方只是随口一句时，回复按**整句**累加到 60 字为止。
  只切在句末标点后，绝不吐半句话；第一句再长也照发。
  真倾诉那条预算放宽到 180 字——她这时候本来就该多接一句。

两个过滤器都会**跳过含 `<<<` 的工具标记行**：那些是功能指令不是文本，
被截掉的话名片/表情包/语音就全都不触发，而且表面完全看不出来
（实测踩过：before_len=64 → after_len=7，一张名片就没了）。

### 像人一点的四项（第二批）

压得太一刀切会出另一种机器味，所以配套放开：

| 开关 | 默认 | 作用 |
|---|---|---|
| `DL_SENPAI_PRIVATE_TRIM_CHARS` | 150 | 私聊单独的预算。用群聊的 60 会把她压成客服 |
| `DL_SENPAI_CASUAL_PROMPT_MAX_CHARS` | 25 | 「随口一句」的长度上限，原先 15 留了缺口 |
| `DL_SENPAI_SILENCE_PROB_GROUP` | 0.1 | 群里随口一句时「看见了但不接」的概率 |
| `DL_SENPAI_TYPING_JITTER_RATIO` | 0.35 | 打字间隔 ±35% 抖动，否则每条都等一样久 |

沉默只作用于**非强制**触发（插嘴、概率醒）：`@` 和私聊仍然必回，
装作没看见就是坏了，不是像人。正经提问（带问号、含求教词）也不参与沉默。

抖动放在 `_human_pause` 里而不是纯函数 `_humanize_pause_ms` 里：
后者有单测按确定值钉节奏规则，掺随机数会让测试变成薛定谔的。

### 反 AI 味：`humanize.py` + 可量化指标

来源：`sakurawwwxh/qq-agent-plus`（`src/llm/humanize.js`、`docs/HUMANIZE.md`）。
它最值钱的不是代码，是把「像不像人」拆成了**能数的东西**：

    aiTellRate            命中助手腔的比例        ← 最影响 AI 味
    duplicateOpenerRate   开头 6 个字重复的比例   ← 开场白模板化
    questionRate          带问号的比例            ← 全在反问和全在自答都不像真人
    avgChars/medianChars/maxChars                ← 长度分布
    cjkRate               中文占比（防混进英文模板）

    python scripts\humanize_eval.py --n 3

**清洗分两档**（分法照搬，因为分法是对的）：

| 档 | 内容 | 处置 |
|---|---|---|
| 严重 | AI 自指/免责、客服收尾、**自曝检索**、**元话语** | 整句删，删空退回原句 |
| 轻微 | 首先/其次/综上所述/需要注意的是 | 只改连接词，句子留着 |

「自曝检索」和「元话语」是我们这个模型特有的，原仓库没有：
实测她会说「知识库里没查到跟天气相关的信息」「回他：…」「给你几个小招」。
只吃自指句式（`我的知识库/我搜了一下`），不吃裸词——
「你用搜索引擎查一下」是正常建议，不能顺手删。

**清单压平**：随口一句时把分类清单合成一句。群里没人这样说话：

    看你想吃哪类
    省事：番茄鸡蛋面 / 饺子      →  看想吃哪类，省事：番茄鸡蛋面 / 饺子
    下饭：青椒肉丝 + 米饭

只在随口一句时压平：答疑本来就需要分点。

**实测（18 条随口闲聊，n=3）**

| 指标 | 接入前 | 接入后 |
|---|---|---|
| aiTellRate | 22.2% | **0%** |
| avgChars / maxChars | 37 / 55 | 37 / 61 |

`DL_SENPAI_HUMANIZE_ENABLE`、`DL_SENPAI_HUMANIZE_SOFT_ENABLE` 可关。

### 梗密度：每轮一贴的分档（`meme.py`）

来源：`sakurawwwxh/qq-agent-plus` 的 `memeDensityPrompt`。
人设里那句「可以轻度接梗」等于没约束：实测要么一轮堆几个梗，要么正经答疑里硬塞一个。
所以做成**每轮定档 + 纪律**（一轮最多一个、不解释、不复读、不贴合就不用）。

| 档 | 什么时候 |
|---|---|
| `off` | 真倾诉、正经答疑（报错/配装/考试…） |
| `light` | 吐槽、随口闲聊：接住刚冒出来的，不主动抛 |
| `normal` | 对方自己在用梗（笑死/破防/离谱…）：接住是本分 |
| `heavy` | 只能手动配，不自动选 |

`DL_SENPAI_MEME_LEVEL=auto|off|light|normal|heavy`，auto = 按上面的规则自动定档。
显式配了就照配置（配 `heavy` 连真倾诉也会玩梗，这点自己权衡）。

措辞上刻意不出现「他/对方/回一句」：提示词里一旦有第三人称或祈使短语，
模型会切成「替用户起草回复」，输出「回他：…」「给你几个版本」。这个坑踩过两次。

### 她以为自己在「交稿」——根因与修复

清洗层再怎么删，都会反复出现这类输出：

> 想回的话，最自然的一句就是：“哪家？避个雷。”
> 共情型：…／追问型：…
> 你是想回他一句吧？

**根因不在措辞，在位置。** 两条合起来就够她误判了：

1. 模型收到的 user 消息是 `群友：好困啊` —— 一条**聊天记录**，不是跟她说的话；
2. system 是四千多字「怎么写 / 格式是 / 末尾要写指令」的**规范文档**。

一段待处理的对话 + 一份写作规范，任务自然被理解成「产出一条回复」。她是在写稿，不是在说话。

**改了三处，越靠后越管用：**

| 位置 | 内容 |
|---|---|
| 人设顶部（【你在场，不在交稿】） | 说明`昵称：这句话`是刚有人在群里说，不是让你分析；列 3 条 ❌ 反例 |
| 本轮提示末尾 | 「你自己怎么想就怎么说，不要写「可以这样回」「共情型」」 |
| **状态栏（最后一条 user 消息）** | 「你就在这个群里，直接说自己的反应」 |

第三条最有效：同一轮里位置越靠后越管用（之前挪语气提示量过，安慰率 22%→55%）。
写进 system 中段的那类规则，基本压不住——人设四千字里的一句，权重太低。

**顺带修掉一个测量错误**：空跑（`dryrun.py`）原来没接状态栏，
既没有当前时间也没有「正在跟你说话的人」，而线上有。
于是「干跑测出来的性格跟线上不一样」——现在干跑走同一条 `_build_status_bar` 路径，
数字才可信。修完立刻看到效果：她开始用真实时间说话（「周日这个点」「下午四点」），
以前空跑里她是没有时间感的。

**数据（关掉清洗量模型原始倾向，24 条随口闲聊）**

| 指标 | 修前 | 修后 |
|---|---|---|

### 翻案腔等机械感规则：`natural-talk`

来源：**chengzhi-c/natural-talk**（「让 AI 像人说话的完整规则集」，SKILL.md）。
它比 humanize.js 更进一步：把 AI 腔按**句式**归类，不按词。摘了 7 条对群聊有用的：

| 规则 | 病灶 | 处理 |
|---|---|---|
| 翻案腔 | 「不是A，而是B」——没人主张过 A，先立个 A 再推翻 | 删否定面留肯定面 |
| 升华 | 「不仅是A，更是B」——把小事抬成大命题 | 改写成「这是B」 |
| 首句壳 | 「先说结论：」「说白了，」「说到底，」 | 删壳，内容留着 |
| 翻译腔 | 「这意味着…」「对于新手来说，」 | 删 |
| 结尾升华 | 「这背后是…」「从某种意义上」 | 删该分句 |
| 复述开场 | 把对方刚说的话重说一遍才接话 | 删复述小句 |
| 清单 | 一条回复里 ≥2 个「短标签：」 | 只留第一项 |

**翻案腔必须留放行口**。它那条放行条款很关键：被否定的观点真实存在过才不算翻案。
用户先问「Redis 缓存为什么没生效」，回「不是缓存的问题，是连接池」是**纠错**、是信息本体，
不能删。判据：连续两字重合，或去掉虚词后实词有交集（「钱的问题」对「是不是钱不够」也算）。

**复述开场**（natural-talk D7）：实测「崩不住了，作业写到两点」→
「这确实挺惨的——凌晨两点还在写作业，基本是在硬撑了」，前半句就是把话重说一遍。
真人直接接后半句。做成「逐小句算实词重合度，命中就删」。

### 出站清洗踩过的坑

1. **标记行是功能指令，任何清洗都不许碰**。CARD 的 JSON 里 `", "` 正好命中
   「逗号+引号」的标点规则，引号被删、JSON 碎掉、`card_actions` 变空、名片整个失效。
   现在所有清洗函数入口先做 `_protect_markers`：标记行换占位符，洗完换回来。
2. **单句超预算照样发**：她回过一句 79 字的「可以回群友，“看几个人…我直接投一票。」，
   整段只有一个句号，按句切等于不切。现在第一句仍超预算时退到**逗号级**切一刀——
   切在逗号后仍是完整小句，不算说半句话。
3. **删一半比不删更难看**：答疑那轮她写了「首先…先让群友补充三点」+ 一张 markdown 表，
   第三人称元话语删掉后只剩「麻烦补充一下」和一行 `|---|---|---|`。
   现在检测到表格残行、括号/引号不成对、以冒号或竖线收尾，就整条退回原文。
4. **整条都是模板时先捞引号里的台词**：「共情型：“兄弟受苦了”」删完是空的，
   但引号里那句是她写好的话，直接发反而最自然。

1. **单句超预算照样发**：她回过一句 79 字的「可以回群友，“看几个人…我直接投一票。」，
   整段只有一个句号，按句切等于不切。现在第一句仍超预算时会退到**逗号级**切一刀——
   切在逗号后仍是完整小句，不算说半句话。
2. **删一半比不删更难看**：答疑那轮她写了「首先…先让群友补充三点」+ 一张 markdown 表，
   第三人称元话语删掉后只剩「麻烦补充一下」和一行 `|---|---|---|`。
   现在检测到表格残行、或以冒号/竖线收尾就**整条退回原文**。
   判据只看结构不看长度——正常删除（「天气不错。不过知识库里没查到…」→「天气不错。」）
   是要的效果，不能因为变短了就回滚。
3. **元话语前缀用逗号**：「可以回他,“…」不是冒号，只认冒号会漏。

### 跨场合对话流（`cross_chat.py`）

从 `ai-companion` 包搬过来的唯一一个我们没做过的东西。它那个包的核心主张是：
决定一个陪聊像不像人的不是模型，是「记不记得你」——而病根不是记忆太短，
是**账本分错了维度**：

    ChatMemory 按会话存 → 群 A 一本、群 B 一本、私聊一本
    同一个人换了地方，她就失忆

三层现在的分工：

| 层 | 记什么 | 何时注入 |
|---|---|---|
| ChatMemory | 她参与的对话（按会话） | messages |
| RecentChat | 本会话当天**全部消息**（含别人的闲聊） | system prompt |
| **CrossChat** | 她**在别处**实际接过的轮次（跨会话、按时间） | system prompt |

**隐私硬规则**（比原实现收紧的一处）：原包不区分场合、全部渲染，群里能看见私聊内容。
这里写死 **私聊内容只允许出现在私聊**：群里只注入「其它群」的片段，
私聊里可以看见群里的公开内容。泄漏一次比「记住」重要得多，所以这条没有开关。

`DL_SENPAI_CROSS_CHAT_ENABLE`（默认开）、`_RECENT_N`（8）、`_MAX_CHARS`（800）、
`_MAX_ENTRIES`（600）可调。

**没搬的部分，以及原因**：

- **自动分条 + 条间停顿 + 长停顿**：`bubble_max=1` 是明确定的（一条一条刷屏更烦人），
  单条发送没有「条间」可言。
- **Waker 的潜水状态机**：我们已有 `agent_trigger` 的触发策略，语义重复。
- **memory.js 的按人账本**：`person_memory.py` 比它全（vibe / style / relation / moments）。
- **transport-onebot.js**：我们走 nonebot + NapCat，比手写 WS 客户端成熟。
- **Humanizer 的 1200ms 打字下限**：这条搬了一半——把 `typing_delay_ms_min`
  从 400 提到 900（真人回一句「嗯」也不会 0.4 秒就出来）。

### 两个 dotenv 的同名键会告警

加载顺序是 `(.env, .env.dev)`，后读的 `.env.dev` **覆盖** `.env`。
于是「我在 `.env` 里改了这项怎么没生效」要排查很久。
不改顺序（本地覆盖是合理设计），但启动时会打一条
`config.dotenv_shadowed`，列出被盖住的键名。

结论：提示词层对「吐槽」无效，对「真倾诉」有效；**真正把吐槽那条压下来的是
出站过滤**，不是模型听话。

后置让模型自己改的三条路都不成立，别再试：这个模型 `max_tokens<=128` 时正文为空
（推理先把额度吃光），给到 256 又不肯只答一个字；让它改写则输出
「可以回得更具体一点…温柔版：」这种点评，压根不是要发的话。

所以现在的做法是：判定为吐槽时，按**逗号级**把安慰那个小句剪掉
（`tone.strip_comfort_clauses`）。整句砍会把有用的话一起扔，所以只删小句；
删完不足 8 字、或剩下「可以这样回」这种元话语残渣，就退回原文——
宁可留一条安慰，也不能发一条残渣。剩下那 11% 就是这些被守卫跳过的情况。

**上下文两道闸**：条数由 `DL_SENPAI_MEMORY_RECENT_TURNS`（默认 24 条）管，
长度由 `DL_SENPAI_HISTORY_MAX_CHARS`（默认 12000 字）管。
为什么两个都要：有人贴一段报错日志、或者转一段聊天记录，一条就上万字，
24 条照样能把上下文塞满。字符预算只作用于「读给模型」，
**绝不在写回时删磁盘记忆**——那是用户的聊天记录。

人设防漂移：`python -m src.plugins.dl_senpai.persona_lint`（`pytest` 里也会自动跑）。

## 已知问题与改进（维护备忘）

### 禁言话术曾「复读 + 装傻」（2026-03）

现象：禁言后学姐反复说「已经帮你禁言了」；对方还能说话却说「发不了消息」；并硬往「有没有心事、来跟学姐说说」上引。

原因简要：
- 人设里禁言说明不够硬，模型爱复读上轮成功话术；
- 「发不了消息」与短时禁言现实不符（几十秒就解禁，且对方正在发言）；
- 小模型易滑向心理咨询腔；
- 辱骂也会触发「补写 MUTE」补救，被误当成「对方要求禁言」。

已做改进：
- `persona.py`：禁止倾诉腔；禁言口头规则改为「没写 <<<MUTE>>> 不许说禁了 / 对方在说话就别说发不了」；
- `persona.py`：主提示词改为「活人感」优先（先反应情绪、短句口语、禁止客服/咨询收尾、禁止复读开场白）；
- `style.py`：发送前清掉「发不了消息」与心事套话；本轮未真正禁言时清掉「已经帮你禁言了」；
- `handlers.py`：仅「明确要求禁言」才补救 MUTE；辱骂未禁成不再贴系统说明。

### 联网曾断开（已接回，2026-03）

群聊链路一度没挂上 `<<<SEARCH>>>` 检索。现已重新接入：默认 `DL_SENPAI_SEARCH_ENABLE=true`，问新闻/天气/股价等会实时搜再答；纯闲聊不每句搜。

中转站 502/503 时会重试中转，**不再**自动切本地 Ollama（避免小模型答非所问）。若要本地推理，需手动设 `LLM_PROVIDER=ollama`。

纯表情/贴纸曾被误当成「你好」（空正文兜底写错）。现已改为识别 face/mface/表情图，喂给模型「（发了个表情…）」。

引用别人消息再 @学姐时，会把【引用消息】+【我现在说的】一起交给模型。

群里 @ 和表情包不好发在同一条时：可先 `@学姐`，**60 秒内**再单独发表情包，也会当成找她；或直接「回复学姐的某条消息」再发表情包。
