# 人设卡

一张卡 = 一个 md 文件 = 一份「她是谁」。正文顶替 `persona.py` 里那份 `SYSTEM_PROMPT`，
其余（格式说明、场景补充、工具说明、各项简报）全部照旧叠加。

## 怎么用

    /人设            看有哪些卡、本会话正在用哪张
    /人设 学姐2      本会话换成这张卡（下一句生效）
    /人设 默认       本会话取消绑定，回到 persona.py 那份
    /人设 体检       逐张检查（AI 味、硬规则位置等，和 persona.py 同一套规则）

只有 `DL_SENPAI_AGENT_ADMIN_QQ` 里的号能用。**没有做成模型工具**：人设卡决定她是谁，
一旦让模型能改，群里任何一句「把你自己换成…….」就能生效。

## 卡长什么样

    ---
    id: 学姐2
    name: 小满
    groups: 1050332675, 1056066897
    description: 另一个群里更嘴硬的那版
    ---
    （正文：就是人设本身，写多长都行）

- `id`：唯一标识，缺省用文件名
- `name`：展示名，缺省同 id
- `groups`：**声明**这些会话默认用它（可写群号、`group:105`、`*`）
- `description`：一句话说明，只出现在列表里
- 全部键都可省略；没有 front-matter 的 md 也能用（整篇当正文、文件名当 id）

## 目录里已经有的那张：`学姐.md`

它是 `python scripts\persona_card.py export 学姐` 从 **当前 persona.py** 导出的副本，
3695 字，和线上那份逐字相同。front-matter 里记了两行：

    source_ref: persona.py      # 从哪来
    source_hash: 3f9c1b…        # 导出时的正文指纹

用途：
- 想在「现在的她」基础上改一版给某个群 → 复制成 `学姐2.md` 再改
- 想让她以卡为准（`persona.py` 退成兜底）→ 在 `.env` 里写
  `DL_SENPAI_PERSONA_CARD_DEFAULT=学姐`，或对某个群 `/人设 学姐`

**它现在没有绑定任何会话**，所以线上跑的还是 `persona.py` 那份。这一点是故意的：
你平常改人设都是直接改 `persona.py`（热加载），一旦让卡成为默认，那些改动就不再
生效，而且不会有任何报错。

### 两份文案并存的规矩

同一个人的文案存在两处（`persona.py` 与这张卡），就必须能一眼看出漂没漂：

    python scripts\persona_card.py list
     =  学姐   学姐   3695 字  -        ← = 与 persona.py 一致
     ≠  学姐2  小满   3610 字  group:105 ← ≠ 已漂移（改过卡，或 persona.py 后来改过）
       README 之类不会出现在这里

漂了之后二选一：**以卡为准**（删掉卡里的 `source_hash` 行，从此不再对账），
或者**重新同步**（`export 学姐 --force`，把卡刷回 persona.py 的现状）。
别放着不管——「改了说明书，没改生效的那份」是这类系统最典型的故障。

## 三种改法，改的是同一份数据

| 场景 | 用什么 |
|---|---|
| 日常切某个群用哪张卡 | 控制台「学姐自设」页的卡片面板，或群里 `/人设 <卡名>` |
| 批量/脚本 | `python scripts\persona_card.py bind group:105 学姐` |
| 让卡成为全局默认 | `.env` 的 `DL_SENPAI_PERSONA_CARD_DEFAULT`（要重启 bot） |

三条路写的是同一个 `bindings.json`，bot 侧按 mtime 热加载，不会出现
「控制台显示绑了、实际没生效」。

## 谁生效：解析顺序

1. **显式绑定**（`/人设 xxx`，写在 `bindings.json`）
2. 卡自己声明的 `groups`（含 `*`）
3. `DL_SENPAI_PERSONA_CARD_DEFAULT` 指定的默认卡
4. 都没有 → **回落 `persona.py`**（改造前的行为，一个字不变）

绑定压过声明：文件里写的 `groups:` 只是开局建议，管理员在群里点过名的那张才算数。

## 几条硬规矩

- 目录为空 / 卡全部读不出来 / 功能关掉（`DL_SENPAI_PERSONA_CARD_ENABLE=false`）
  → 一律回到 `persona.py`。加这层功能不该让「她自己」变成不可用状态。
- 正文为空的 md 会被丢弃（在列表里看到一张空卡比看不到更糟）。
- 卡的体检结果不影响使用，只在 `/人设` 列表里提示。
- **不要**把同一份人设既写进 `persona.py` 又写成卡：两份必然会漂移，
  漂移之后「她到底是谁」取决于这一轮绑没绑卡——这种问题最难查。
- 按卡切换微调风格（`speak_styles`）故意没做：风格库是全局单例，
  按群切会串台（A 群换软萌，B 群跟着变），比不切更糟。
